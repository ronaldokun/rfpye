# Repository Guidelines

## Project Structure & Module Organization
- `rfpye/` holds the Python package. Most modules are generated from notebooks and start with an "AUTOGENERATED" header.
- `rfpye/cyparser.pyx` is the Cython extension source; `rfpye/cyparser.c` is generated.
- `nbs/` contains the nbdev source notebooks and helper scripts (for example, `nbs/test_parser.py`).
- `docs/` is the built documentation site. Project metadata and modern build configuration live in `pyproject.toml` (primary). Legacy `settings.ini` and `setup.py` remain for nbdev compatibility but should not be manually edited—keep them in sync via `nbdev_update_lib`.

## Build, Test, and Development Commands
**Using uv (modern approach):**
- Create a dev environment: `uv venv .venv` (or `uv sync` to set up and install all dependencies).
- Install in editable mode with dev deps: `uv pip install -e .[dev]`.
- Regenerate the library from notebooks: `nbdev_build_lib`.
- Sync changes from `rfpye/` back into notebooks: `nbdev_update_lib`.
- Build docs: `nbdev_build_docs` (requires `quarto`).
- Run notebook tests: `nbdev_test_nbs`.
- Build distribution artifacts: `uv build` (PEP 517) or `python setup.py sdist bdist_wheel` (legacy).

**Using Makefile (if bash-compatible shell available):**
- `make rfpye` → regenerate library
- `make docs` → build documentation
- `make test` → run notebook tests
- `make dist` → build wheels and sdist

Note: Makefile assumes bash; on Windows use WSL or run commands directly.

## Coding Style & Naming Conventions
- Python uses 4-space indentation. Black is listed in dev deps; keep formatting consistent with its defaults.
- Use `snake_case` for functions/variables, `PascalCase` for classes, and `UPPER_CASE` for constants.
- Do not edit autogenerated modules; change the source notebooks in `nbs/` and rebuild.

## Testing Guidelines
- Tests are notebook-based via nbdev (`nbdev_test_nbs`). There is no standalone pytest suite.
- `nbs/test_parser.py` is a manual runner for local validation.
- Avoid committing binary `.bin` inputs or logs (ignored by `.gitignore`).

## Commit & Pull Request Guidelines
- Git history shows short, imperative subjects; emoji prefixes like `:bug:` or `:sparkles:` appear and English/Portuguese are both used. Follow that style and keep subjects concise.
- PRs should include a summary, how you tested, and note any regenerated artifacts (library/docs). Link issues where relevant and add screenshots for doc/UI changes.
